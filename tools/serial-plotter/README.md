# Load Cell Serial Plotter

Pico 2 WのUSBシリアルまたはBLE出力を受信し、生のテキストと測定値のグラフを同時に表示するPC用Rustアプリ。
起動時は重心測定画面を表示する。**Sensor graphs** ではraw・PC delta・PC kgの3段グラフを表示する（既定の選択はLC1）。最新ファームウェアはrawのみを送信し、ゼロ点調整・重量換算はモニターで行う。旧形式のUSBログも読み込める。

## 起動（Windows / PowerShell）

リポジトリのルートで実行する。

```powershell
.\tools\serial-plotter\run.ps1 -Port COM5
```

初回は依存ライブラリのダウンロードとコンパイルが行われる。RustとWindows用MSVCビルド環境が必要である。
PowerShellのスクリプト実行が制限されている環境では、以下を直接実行できる。

```powershell
cargo run --locked --manifest-path tools/serial-plotter/Cargo.toml --target x86_64-pc-windows-msvc -p serial-plotter -- --port COM5
```

1. VS Code等で開いているCOM5のシリアルモニターを閉じる。
2. 接続している全ロードセルを無負荷にして、アプリの **Connect** を押す。
3. **Auto zero on connection** が有効なら、測定対象を取り除いて接続する。空の台は載せたままにする。マイコンが各HX711を初期化・500 ms安定待ちした後、PC側で有効データを蓄積してゼロ点を取得する。画面の `Zeroing` 表示が消えるまで台を静止させる。取得結果は **Zero options** で確認できる。
4. 荷重を変えると、測定値とグラフが更新される。受信ログは下部の **Serial log** で開く。

ポートは手入力、または **Connection details → Available ports** で選択できる。同じメニューの **Refresh ports** で一覧を更新し、Baudを設定する。BLEのアドレス指定も **Connection details** にある。
ポートを開けない場合は画面上部に理由を表示する。別アプリによる占有やUSB接続を確認してから再接続する。
自動再接続は行わない。再接続は新しい表示履歴を開始し、自動ゼロ調整が有効ならPC側で再調整する。

## PC側のゼロ点調整

測定値カードの下の **Zero load** で手動調整し、**Zero options** で自動調整を設定する。対象チャンネルは **Sensor settings / calibration** の **Use** で指定する。USB/BLEのどちらでも同じ操作で、マイコンへのコマンド送信は不要。

- **Auto zero on connection**（既定ON）：接続後とファームウェアの新しいセッション通知時に一度だけ取得する。有効な全対象センサーのデータが揃い、平均時間分の正常受信が続くまで待つ。載荷中に自動でゼロを追従させる処理は行わない。保存済みのゼロ点で開始する場合は接続前にOFFにする。
- **Zero load**：接続中に、直近の平均値をゼロ点として再取得する。既定の平均時間は0.5秒、最低3点。測定対象を取り除いて静止させてから押す。異常・欠測・古いデータ・サンプル不足がある場合は全チャンネルの既存ゼロ点を保持し、理由を表示する。
- 対象は校正設定の **Use** がONのLC。グラフ表示用のLCチェックとは独立している。試験で接続していないセンサーは外せるが、実際に台を支えるセンサーはすべて有効にする。
- 重量は `(raw - PC zero) / signed counts/kg`。個別荷重表示、センサーグラフ、重心計算に同じ設定を使用する。ゼロ調整後は旧設定の重心軌跡を消去する。保持済みrawの重量グラフは現在の校正値で再計算する。
- 自動・手動で取得したゼロ点と自動調整設定は、**Sensor settings / calibration** の **Save settings** で保存する。自動調整ONでは次回接続時に保存済みゼロ点を再取得する。公称感度のままでは `Nominal` と表示するため、正確な重量には既知荷重による感度校正も必要。

マイコン側のLEDは初期化・通信・読み取り状態を示す。PCのゼロ点調整中であることはLEDには反映しない。

実機なしで画面を確認するには、以下を実行するか、切断中に **Actions → Sample log** を押す。

```powershell
.\tools\serial-plotter\run.ps1 -Demo
```

デモは提示されたログのraw値を基にした静的なサンプルである。時刻は0.65秒間隔の仮定値であり、実測時刻ではない。画面には **DEMO** と表示する。

## 重心の測定（PC側の設定のみ）

**Center of gravity** では、マイコンの `raw` からPC独自のゼロ点・感度を使って各支持点の荷重を求め、総荷重と水平面内の重心を表示する。ファームウェアの `delta` と `kg~` はこの計算に使用しない。正常な `raw status=no_tare` もPC側で校正できる。

画面上部の **TOTAL LOAD** は4台の現在の合計荷重を **kgf** で表示する。PCゼロ点を差し引いた各セルの平均荷重を合計し、ゼロ近辺や重心を計算できない点配置でも表示する。4台すべての有効化、ゼロ設定、新鮮な有効データが必要で、欠測時は `--` と理由を表示する。未校正のセルがあれば `Uncalibrated` を表示する。kgfは力の単位で、1 kgf = 9.80665 N。この表示は既知質量で校正したkg相当値を標準重力の規約でkgfとして扱うもので、地域の重力加速度の補正は行わない。

座標系は**前側2個のロードセル中心の中点を原点、右を+x、後ろを+y**とし、単位はmmである。

| 測定点 | 初期x座標 (mm) | 初期y座標 (mm) |
|---|---:|---:|
| UR / Upper right（右上・前右） | 300 | 0 |
| UL / Upper left（左上・前左） | −300 | 0 |
| LR / Lower right（右下・後右） | 300 | 2000 |
| LL / Lower left（左下・後左） | −300 | 2000 |

設定は2層に分かれる。**1. Measurement point coordinates** で測定点ごとのx・yを指定し、**2. Point to sensor assignment** で各点にどのLCを割り当てるか指定する。座標を編集しても割り当ては変わらず、割り当てを変更しても座標は変わらない。原点は共通の固定基準として扱い、入力に合わせて自動移動しない。

既に使用中のLCを選ぶと、2つの測定点のLC番号を自動で交換する。例えば右上をLC1からLC3にすると、右下がLC1になる。校正値・ゼロ点・Useは物理的なLC番号に属し、測定点と一緒には移動しない。保存済みの旧 `x1 / x2 / y / dx / dy` 形式は従来の式から4点の座標に変換して読み込み、新しい保存形式では `points` と `channels` を別々に記録する。

配置図は**前が上・右が右**で、描画座標を `(x, −y)` とする。数値表示・CSV・t–yグラフは指定どおり後方が正のyである。初期値は幅600 mm・奥行き2000 mmのフレームで、LC1=(300,0)、LC2=(-300,0)、LC3=(300,2000)、LC4=(-300,2000)。実際のセンサー中心位置に合わせて調整できる。

左側に実寸の縦横比を保つ縦長のXY配置図、右側にt-x・t-yグラフを表示する。狭い表示領域では縦に並べる。初期ウィンドウは1440×1000、ログは初期状態で閉じている。**Serial log** で開くと初期高さ150、上端のドラッグで画面高の20%まで変更できる。小さい画面ではこの上限を優先する。上部の **Sensor settings / calibration** タブから位置設定・ゼロ点・感度校正・JSON保存を開ける。**Apply 600 x 2000 mm frame** で寸法だけを既定値に戻せる。保存済み設定は起動時に優先し、このボタンもチャンネル割り当てや校正値は変更しない。

### 設定と校正の手順

画面上部の **Sensor settings / calibration** タブを開く。位置と校正の各欄は初期状態で展開されている。

1. **1. Measurement point coordinates** に4点のx・yを入力し、**2. Point to sensor assignment** で各点のLC番号を選ぶ。数値欄はクリックして直接入力でき、負数・小数にも対応する。
2. センサーを個別に校正する。対象センサーを無荷重にし、受信が安定したらその行の **Zero** を押す。次にそのセンサーだけへ既知荷重を加え、チャンネルと荷重kgを指定して **Capture span (auto polarity)** を押す。感度と極性を同時に求める。台で荷重が分配されている状態で、物体全体の質量を1個のセンサーの荷重として入力してはいけない。
3. 既知の校正値がある場合は **Signed counts/kg** に正負を含めて入力し、**Verified** をチェックする。PCゼロ点もraw値で直接入力できる。ゼロ点がちょうど0の場合も **Zero set** で設定できる。初期感度は公称値で、未検証の感度を含む結果には **Uncalibrated** を表示する。
4. 台を組み立て、測定対象だけを取り除いた状態で安定を待ち、**Capture platform-only zero (all enabled sensors)** を押す。これにより台の自重を差し引く。台を含めた重心が欲しい場合は、台を載せる前のゼロ点を使用する。
5. 測定対象を載せて静止させる。総荷重、各点の荷重、重心 `(x, y)`、2D軌跡と時間グラフを確認する。
6. **Save settings** で保存する。既定の保存先は `%LOCALAPPDATA%\LoadCellSerialPlotter\balance.json`（UTF-8）で、次回起動時に読み込む。寸法、割り当て、使用センサー、ゼロ点、感度、確認状態、平均化・有効性のしきい値、時間グラフの表示秒数を保存する。別名JSONの保存・読み込みも画面のパス欄から行える。保存は明示操作であり、未保存の変更は表示される。

**Use** は実際に台を支持しているセンサーをすべて有効にする。故障した支持点を無効にして計算を継続すると、荷重が欠けて誤った結果になる。2D重心には一直線上にない3点以上が必要である。再接続やUSB復帰後はゼロ点を再確認する。

計算は `wᵢ = (平均rawᵢ − PCゼロ点ᵢ) / 符号付き感度ᵢ`、`W = Σwᵢ`、`xCG = Σ(wᵢxᵢ)/W`、`yCG = Σ(wᵢyᵢ)/W` である。[FUTEKの多点荷重による重心測定の説明](https://www.futek.com/applications/center-of-gravity-measurement)に対応する。水平な支持面で静止し、荷重がすべてセンサーを通る条件で水平重心を求める。高さ方向は求めない。動作中は慣性力も作用するため、軌跡は荷重中心の変化であり、物体の重心移動そのものとは限らない。

### 重心の軌跡・時間グラフと欠測

- 2D配置図は**過去1秒の軌跡**を淡い色で描き、古い線分ほど細く・透明度を高くする。最新の有効位置は濃い赤色の点で表示する。
- 各測定点には測定点名と割り当てたLC番号を表示し、無効な点には **OFF** を付ける。現在の荷重と有効サンプル数は4台の一覧にまとめ、測定点の詳しい受信状態・荷重はホバーで確認できる。重心が計算できなくても、正常なセンサーの個別表示は継続する。通信状態は受信データからの判定であり、電気的な接続検出ではない。
- 荷重バーは各点の真横を下端として上へ伸びる。4点共通の **Bar max** で満杯の荷重を調整する（起動時50kgf、表示専用で保存対象外）。満杯を超えると `+`、負荷重には `!` を表示する。実際の数値は4台の一覧とホバーに表示し、負荷重を上向きバーへ変換しない。公称感度には一覧で `Nominal`、ホバーで `*` が付く。
- 切断、無受信、データの有効期限超過、タイムアウト、読み取り異常、未復旧の欠落ではバーを消して **×** を表示し、理由をホバーに示す。全体の切断は上部のバッジ1箇所にまとめ、配置図は灰色の×、測定値は `--` にする。接続中の個別センサー異常は赤い×で区別する。ゼロ点待ち・平均用サンプル不足は空の丸印、無効なセンサーは灰色で表示してバーを描かない。無効でも受信状態は確認できる。
- **t–x** は左右位置、**t–y** は前後位置を別々のグラフに表示する。横軸はPC受信経過時間、縦軸はmm。**CG history → Window** で1〜300秒を選ぶ。履歴は最大300秒かつ24,000点まで保持する。
- 既定では直近0.5秒の各センサーのraw平均を使用し、3点以上を要求する。**Averaging and validity limits** で平均時間、最低サンプル数、最大経過時間（既定0.5秒）、チャンネル間の受信時刻差（既定0.2秒）、最小総荷重（既定0.1kg）、負荷重の許容幅（既定0.02kg）を設定する。
- 有効な新しい受信データを処理した時点で重心履歴を更新し、画面の再描画だけでは点を追加しない。受信チャンク内の複数行はまとめて処理されるため、重心履歴の点数は生のサンプル数とは異なる。同じ受信時刻の結果は最後の値を保持する。
- 使用中のセンサーに欠測・飽和・古いデータ・時刻差超過がある場合、総荷重が小さい場合、ゼロ点未設定の場合などは最新重心を表示せず理由を出す。故障、欠落通知、設定変更、再接続の前後は軌跡をつながない。平均値にもエラー前の値を混ぜない。
- 小さい負値はしきい値内ならそのまま計算し、ゼロへ丸めない。許容幅を超える負荷重は極性・ゼロ点・接触を確認する表示となる。`raw=-1` だけを理由に読み取り異常とは判定しない。
- マイコンから測定時刻が送られないため、判定に使用するのはPC受信時刻である。非同期の4台を同時測定にする機能ではない。
- **Copy values** で現在の総荷重、重心、各センサー荷重と公称値使用の有無をコピーできる。

重心画面の模擬データは、切断中の **Actions → CG sample** または以下で確認できる。最後の値は総荷重100kg、`x = −36mm`、`y = 419mm` である。デモ設定のファイル保存と実データでの校正操作は無効で、実機へ接続するとデモ前の設定に戻る。

```powershell
.\tools\serial-plotter\run.ps1 -CgDemo
```

## 直近1秒の有効サンプル数

測定値カード下の4台一覧にある **samples / 1 s** は、各LCについて `(現在時刻−1秒, 現在時刻]` に受信した正常rawの個数を表示する。公称10/80 SPSや描画FPSを表示するものではない。
`timeout / protocol / saturated`、飽和コード、解析不能な行、診断行を除く。正常な `no_tare` のraw、負値、0、−1は数える。無受信になれば時間経過で0になり、グラフの表示チャンネルや時間追従の停止には影響されない。デモ時だけはデモ末尾の時刻を基準とする。

## 表示仕様

- 上部ツールバーは接続操作と状態バッジ、中央は測定値カード・各LCの一覧・グラフに分ける。総荷重と重心x/yは28pxの等幅数字、各LCの荷重は18pxで表示する。
- 座標系や凡例は **?**、補足説明はホバーで開く。ゼロ点取得待ち、未校正、個別センサー異常、接続エラーなど、測定判断に必要な状態は表示したままにする。
- 下部の **Serial log** でログを開閉し、**Actions** に履歴消去とデモをまとめる。受信行数・解析エラー数・欠落数は下部の統計欄へ表示する。ログを閉じても受信・履歴保持は続く。
- シリアルモニターは全チャンネル・起動メッセージ・エラーテキストを表示する。グラフのチャンネル選択はモニターに影響しない。
- `LC1`〜`LC4` の `raw=整数` を解析し、PC校正値でraw・delta・kgの3段グラフに表示する。旧形式の `raw=整数 delta=整数 kg~=有限数` も受信できる。各グラフの **Auto Y** は表示時間範囲内の値に上下の余白を加えて縦軸を調整し、一定値にも幅を持たせる。
- 各グラフの **Lower**（下限）と **Upper**（上限）へ数値を入力し、**Apply Y** または Enter で適用すると縦軸を固定する。負数・小数にも対応する。下限≧上限、空欄、非数値、無限大などはエラーを表示し、直前の有効範囲を保つ。**Auto Y** を再び有効にすると自動調整へ戻る。
- 横軸はPCでの受信経過時間である。マイコン上の測定時刻ではなく、一度の読み取りに含まれる行は同じ時刻になる。
- `status=timeout`、`status=saturated`、`status=protocol` は欠測である。`protocol` はDOUTの状態検査またはクロックHigh時間の検査に失敗したことを示す。該当センサーは次の読み取り前にリセットと500 msの安定待ちを行う。数値ゼロへの置換や欠測区間をまたぐ線の補間は行わない。
- `raw=整数` と旧形式の `raw=整数 status=no_tare` は、PCゼロ点があればdelta・kgへ換算できる。未設定のゼロ点から重量を推定しない。
- 最新ファームウェアはゼロ点調整を行わない。PC側の待機・失敗は **Zero load** の横、取得結果の詳細は **Zero options** に表示する。旧ファームウェアの `Tare` メッセージは互換性のため読み込み、**Actions** 内の `Legacy firmware tare` として表示する。
- `Dropped LCn samples=N (transport backlog)` はファーム側の欠落通知として数え、上部の `firmware drops` に合計を表示する。該当チャンネルは次の測定点から新しい線分に分け、欠落区間を線でつながない。通知自体を測定値として追加しない。正確な欠落時刻は出力されていないため推定しない。
- `raw=-1`、負値、ゼロ、急変値は保持する。PC重量グラフは各サンプルを換算し、上部の重量と重心は設定時間の平均から計算する。**PC calibrated graphs** をOFFにすると旧ファームウェアのdelta・kgを表示する診断用モードになり、新形式ではその2項目は空欄になる。
- **Follow latest** は横軸を最新データへ自動追従させる。縦軸の固定／自動調整とは独立している。**Window** は表示時間幅を変更する（開始直後は経過時間分まで）。
- **Follow latest** を外すと時間範囲が止まり、ドラッグ・ホイールで保持中の過去データを移動・拡大できる。**Auto Y** を外すと縦軸もドラッグ・ズームできる。再描画で操作をリセットしない。受信とモニター表示は続く。**Follow latest** を再び有効にすると追従を再開する。
- **Actions → Clear measurement history** は表示履歴と欠落件数を消去する。接続とPCのゼロ点・感度は保持する。再接続時のゼロ点再取得は **Auto zero on connection** の設定に従う。
- ログ内の **Copy log** は保持中の受信テキストをクリップボードにコピーする。ログの自動保存は行わない。

保持上限はモニター2,000行、各チャンネル10,000件、受信待ち64チャンク（各最大4,096バイト）である。
10,000件にはエラーや未調整の読み取りも含む。正常値だけの場合の保持時間の目安は以下の通り。

| 出力条件 | 4台合計の測定行 | 各チャンネルのグラフ履歴 | 全チャンネルの文字ログ |
|---|---:|---:|---:|
| 現在の基板：10 SPS/台 | 約40行/秒 | 約1,000秒（16分40秒） | 約50秒 |
| 将来RATEを変更：80 SPS/台 | 約320行/秒 | 約125秒（2分5秒） | 約6.25秒 |

診断行が増えると文字ログの保持時間は短くなる。Windowを保持時間より長くしても、破棄済みの履歴は戻らない。
定期的な再描画要求は50 ms間隔（約20回/秒）。受信件数とは独立しており、1画面更新で複数点を追加する。
固定のサンプリング周期やLC1～LC4の到着順は仮定しない。80 SPSはモニター側の模擬試験条件であり、現在のAE-HX711-SIPをソフトだけで80 SPSへ変更する機能ではない。

古い履歴から破棄されるため、長時間追従を停止すると停止範囲のデータも保持上限で失われる。
1行は最大4,096バイトで、超過行と不正UTF-8行はモニターに理由を表示し、次の改行で復帰する。
通常のASCII/UTF-8受信行は改行を除いてそのまま表示する。分割受信された行は連結し、改行前の断片もモニターに表示する。
解析できないLC行はグラフに入れず、エラー件数を増やす。小さなUSB受信片は約10msまたは4,096バイト単位にまとめる。受信キューが満杯の場合は受信スレッドが空きを待ち、一時的な混雑だけでは切断しない。待機中も Disconnect に応答する。継続的にPCの処理能力を超える流量ではOS／USB側のバッファにも依存するため、完全な無欠落記録を保証する機能ではない。

型・境界の見直し：センサー割り当て `Assignment` は4台の順列だけを保持し、JSONからの不正値を構築時に拒否する。計算エラー、受信不可理由、ゼロ待ち理由、USB/BLEの操作エラー、設定入出力エラーは列挙型とし、表示文言は `Display` に分離した。I/Oエラーでは元のエラーも保持する。描画時間幅を除外するために設定値を不正なゼロへ書き換えていた比較処理は、計算入力だけの `CalculationKey` に置き換えた。

方針の適用判断：

- 状態遷移・計算・I/Oの境界は分けるが、GUIの `no_std` 化、新しい移植用抽象層やDIフレームワークは追加しない。
- 有界の履歴には `VecDeque` と明示的な可変更新を維持する。各受信で履歴全体をコピーする純粋関数への一律変換は行わない。
- 分岐の網羅性が必要な状態には `enum` / `match` を使い、数値条件や二択の検査には `if` を使う。すべての数値を別の型で包むことも目的化しない。編集途中の設定は無効値を取り得るため、計算・換算・保存・読み込みの境界で検証する。
- 旧シリアルログと保存済みJSONの互換性は、利用者の測定履歴・校正値を保護するため維持する。旧形式の解釈はパーサーと設定読み込みに限定する。
- 検証は状態遷移・故障・復帰・負荷・画面なしの描画テストで行う。今回追加の形式証明や実機検証を行ったという主張はしない。

検証：61件のテスト（GUI 51件、パーサー9件、doc-test 1件）とClippyを実行。実機USB/BLEの再接続・切断、物理荷重の精度、ネイティブGPU画面の目視確認は今回の検証には含めていない。

## BLE接続

USB/BLE対応ファームウェアを書き込んだPico 2 Wに接続できる。
画面上部の `BLE` を選び、センサーを無荷重にして `Connect` を押す。
5秒間検索した後、Loadcellsサービスを持つ1台に自動接続する。
複数台ある場合はエラー欄に表示されるアドレスを `BLE address` に指定する。
USBを使う場合は `USB` を選び、従来どおりCOMポートを指定する。

マイコンはDTRが有効なUSBを優先する。BLEに接続できてもデータが来ない場合は、
他のUSBシリアルモニターを閉じる。PCの自動ゼロ調整が有効なら、接続先の切り替え時も
測定対象を取り除く。電源専用のUSB接続はBLE送信を妨げない。
現在の配線ではHX711側にも5 V電源が必要なため、無線使用時もUSB電源等を維持する。

BLE受信後はUSBと同じパーサーを使う。重心設定、校正、過去1秒の有効サンプル数、
XY軌跡・t-x/t-yグラフは共通。通知の欠落時は不完全なデータを破棄して軌跡を分断する。
BLEはペアリング・暗号化なしの専用通知サービスであり、仮想COMポートにはならない。
実際の通信速度、電波環境、Windowsアダプターとの相互運用は実機での確認が必要。
